# Oruvia Product Requirements

## 1. Product Overview

Oruvia is a Proptech and Real Estate Marketplace built for the Ogun Digital Summit Hackathon.

The platform connects property seekers with verified landlords and real estate agents in Nigeria.

**Tagline:** Oruvia: Your path to a roof.

## 2. Problem Statement

Finding an apartment in Nigeria often involves physically visiting multiple properties, relying on middlemen, dealing with fake listings, paying inflated agent fees, and wasting time and money.

Landlords and agents also need a convenient way to reach serious prospective tenants and buyers.

Oruvia aims to solve these problems through a centralized property marketplace.

## 3. Product Goal

Enable users to:

- Discover properties based on their needs.
- Search for properties in selected locations.
- Compare available properties.
- Save properties for future reference.
- Contact relevant property listers.
- Request and manage property inspections.
- Explore properties virtually before visiting physically.

## 4. Core Features

### 4.1 Authentication and Account Management

The platform should support user registration, authentication, and account management.

Authentication requirements and user permissions are defined separately.

### 4.2 Property Listings

The platform should support property listings containing:

- Property title.
- Property type.
- Rent or sale classification.
- Price.
- Location.
- Bedrooms.
- Bathrooms.
- Description.
- Amenities.
- Property images.
- Optional video tour.
- Availability status.
- Verification information.

### 4.3 Property Search and Discovery

Users should be able to search and filter properties by:

- Location.
- Rent or sale.
- Price range.
- Property type.
- Number of bedrooms.
- Number of bathrooms.

Search results should make it easy to compare available properties.

### 4.4 Property Details

Each property should provide:

- Photo gallery.
- Property description.
- Price.
- Amenities.
- Location information.
- Property specifications.
- Relevant lister information.
- Verification badge where applicable.
- Contact options.
- Inspection request option.

### 4.5 Favorites

Users should be able to save properties they are interested in.

Saved properties should be accessible for future reference.

### 4.6 Inspection Booking

The platform should support inspection requests for properties.

Inspection modes:

- Physical inspection.
- Virtual inspection.

Inspection functionality should include:

- Inspection date and time.
- Inspection request.
- Confirmation.
- Declining.
- Rescheduling.
- Cancellation.
- Status tracking.

### 4.7 Inquiries and Messaging

The platform should facilitate communication regarding property listings.

Features should include:

- Property inquiries.
- Conversations.
- Messages.
- Inquiry tracking.
- WhatsApp contact as a fallback where appropriate.

### 4.8 Verification

The platform should support verification of relevant users and property listings.

Verification functionality should include:

- Verification requests.
- Verification documents.
- Verification status.
- Approval and rejection.
- Verified badges.

### 4.9 Reviews and Ratings

The platform should support reviews and ratings for relevant real estate interactions.

Reviews should help users make informed decisions and improve trust in the marketplace.

### 4.10 Listing Moderation

The platform should support reporting suspicious properties and users.

Moderation functionality should include:

- Listing reports.
- User reports.
- Report review.
- Listing moderation.
- Appropriate actions against fraudulent activity.

### 4.11 Notifications

The platform should support notifications for important activities.

Examples:

- New inquiries.
- Inspection requests.
- Inspection confirmations.
- Inspection rescheduling.
- Verification updates.
- Listing updates.

## 5. Business Requirements

- Property information should be accurate and relevant.
- Listings should reflect their actual availability.
- Unavailable properties should not appear as available in active searches.
- Inspection requests should contain valid dates and times.
- Inspection statuses should accurately reflect the current state of a request.
- Verification badges should represent approved verification.
- Reviews should be genuine and associated with eligible interactions.
- Suspicious listings should be reportable.
- User privacy should be respected.
- Marketplace interactions should be transparent and reliable.

## 6. MVP Scope

### Must Have

- Authentication.
- Property listings.
- Property search and filtering.
- Property details.
- Favorites.
- Inspection booking.
- Inquiries and messaging.
- Listing management.
- Inspection management.

### Should Have

- Verification.
- Listing moderation.
- Reviews and ratings.
- Notifications.
- Map-based property discovery.

### Future Roadmap

- Mortgage financing.
- Rent-to-own financing.
- Electronic tenancy agreements.
- AI property price estimation.
- 3D and virtual reality property tours.
- Escrow payments.

## 7. Product Principles

- Trust and transparency are essential.
- Property discovery should be simple and fast.
- The experience should prioritize mobile users.
- Listings should provide accurate information.
- Inspection booking should be convenient.
- The platform should reduce unnecessary physical visits.
- User privacy should be respected.
- The MVP should prioritize essential functionality.

## 8. Success Metrics

- A property lister can publish a listing in under three minutes.
- A property seeker can find a relevant property in under one minute.
- An inspection request can be submitted and confirmed within the platform.
- The core marketplace flows are functional and demo-ready.

## 9. Final Objective

Build Oruvia into a reliable property marketplace that helps Nigerians find suitable homes, discover trustworthy listings, and arrange property inspections with confidence.

**Oruvia: Your path to a roof.**
