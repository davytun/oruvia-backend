# KYC Module

## Overview

The KYC (Know Your Customer) Module provides identity verification for **lister roles only** (Agents and Landlords). Listers submit a government-issued ID document, an Admin reviews and approves or rejects it, and approved listers earn the **Verified badge** displayed on their listings.

KYC is a **soft gate**: unverified users can register, log in, browse, search, save favourites, and message. Only **publishing a listing** requires an approved KYC status.

Seekers are out of scope (email verification remains their only gate). Admins are provisioned internally and do not undergo KYC.

---

## Document Policy

### Accepted document types (`document_type` enum)

| Value | Description |
|---|---|
| `NIN_SLIP` | National Identification Number slip |
| `DRIVERS_LICENSE` | Driver's licence |
| `INTERNATIONAL_PASSPORT` | International passport |
| `OTHER_GOVERNMENT_ID` | Catch-all: any other government-issued ID, judged for validity by the reviewing Admin |

The upload UI presents the specific types as *examples*, not an exhaustive allowlist — any valid government-issued ID may be submitted via `OTHER_GOVERNMENT_ID`.

### Explicit non-goals

- **BVN is never collected, entered, stored, or requested anywhere in the flow.** No field, column, or template may add it — combining BVN with SMS OTP is an account-takeover vector and an unnecessary compliance liability. Do not add a BVN field in future iterations without a dedicated security review.
- No automated identity-provider verification (e.g., NIMC lookups). Review is **manual by Admin only**.

## Lifecycle (One-Way + Resubmit)

```
unverified ──upload──▶ pending ──admin approve──▶ approved (terminal)
                          │
                       admin reject (reason required)
                          ▼
                   rejected ──resubmit (max 3 attempts)──▶ pending
```

- Only **one active submission** at a time: a `pending` submission blocks new uploads.
- Each resubmit increments `attempt`; after **3 rejected attempts** the account is locked from further submissions.
- `approved` is terminal in the MVP. Admin-initiated revocation is a fast-follow, not built.
- Rejection emails include the Admin's reason and use the existing `mail` module.

## Architecture & Data Model

### KYC Submissions
- **Table:** `agent_kyc_submissions` (agents) and `landlord_kyc_submissions` (landlords) — per-role tables, consistent with the strict account segregation in the account modules.
  - `id`: UUID primary key (auto-generated via `uuid_generate_v4()`)
  - `user_id`: UUID foreign key referencing `agent_users(id)` / `landlord_users(id)` ON DELETE CASCADE
  - `status`: `pending` | `approved` | `rejected`
  - `document_type`: `NIN_SLIP` | `DRIVERS_LICENSE` | `INTERNATIONAL_PASSPORT` | `OTHER_GOVERNMENT_ID`
  - `document_url`: varchar(255), storage reference to the uploaded ID image (see Document Storage)
  - `attempt`: integer, starts at 1, max 3
  - `reviewed_by`: UUID foreign key referencing `admin_users(id)`, nullable
  - `reviewed_at`: timestamptz, nullable
  - `rejection_reason`: text, nullable (required when rejecting)
  - `created_at` / `updated_at`: timestamptz
  - Partial unique index on `(user_id)` WHERE `status = 'pending'` (single active submission enforced at the database level)

### Denormalized Status on User Tables
- `agent_users` and `landlord_users` gain:
  - `verification_status`: `unverified` | `pending` | `approved` | `rejected`, default `unverified`
  - `verified_at`: timestamptz, nullable
- Updated transactionally alongside submission review. This lets listing cards and search results render the Verified badge without joining KYC tables.

### Document Storage
- Provider: **Cloudinary** (`KYC_STORAGE_PROVIDER=cloudinary`), uploaded server-side via the signed REST API as `resource_type=raw` with `access_mode=authenticated` — originals are never public; reads go through short-lived signed URLs (~5 min) generated by the API.
- A `local` disk provider (`KYC_UPLOAD_DIR`, unguessable generated file names) exists as a dev/test fallback only and is rejected by env validation in production. Object storage swap risk is contained behind the `KycStorageProvider` interface.
- References are stored as Cloudinary public IDs (`{ownerId}-{random}.{ext}` under `CLOUDINARY_KYC_FOLDER`); client-supplied file names are never used.
- Uploaded files are treated as sensitive personal data: access is restricted to the submitting lister and authenticated Admins via authenticated endpoints that stream the bytes (`StreamableFile`), never public URLs.

## Endpoints

### Lister side

Mounted under `/api/v1/agents/kyc` and `/api/v1/landlords/kyc`, each behind the role's existing guard (`AgentJwtAuthGuard` / `LandlordJwtAuthGuard`).

| Method | Path | Auth | Description |
|---|---|---|---|
| `POST` | `/api/v1/{role}/kyc/submit` | Bearer JWT (role guard) | Upload ID document (multipart, `document` file part + `documentType`) and create a `pending` submission |
| `GET` | `/api/v1/{role}/kyc` | Bearer JWT (role guard) | Current verification status, active submission, last rejection reason, attempt counters (drives in-app banner CTAs) |
| `GET` | `/api/v1/{role}/kyc/document` | Bearer JWT (role guard) | Stream own most recent submitted document (`StreamableFile`, never a public URL) |

### Admin side

Mounted under `/api/v1/admin/kyc`, behind the existing `AdminJwtAuthGuard`.

| Method | Path | Auth | Description |
|---|---|---|---|
| `GET` | `/api/v1/admin/kyc/pending` | Bearer JWT (`AdminJwtAuthGuard`) | Review queue of `pending` submissions (agents and landlords merged, oldest first) |
| `GET` | `/api/v1/admin/kyc/:id` | Bearer JWT (`AdminJwtAuthGuard`) | Fetch a single submission with lister details |
| `GET` | `/api/v1/admin/kyc/:id/document` | Bearer JWT (`AdminJwtAuthGuard`) | Stream the submitted document bytes to the reviewer |
| `POST` | `/api/v1/admin/kyc/:id/approve` | Bearer JWT (`AdminJwtAuthGuard`) | Approve; sets user `verification_status = 'approved'`, emits `verified_at`, notifies lister. 409 if already reviewed |
| `POST` | `/api/v1/admin/kyc/:id/reject` | Bearer JWT (`AdminJwtAuthGuard`) | Reject with mandatory reason (10–500 chars); notifies lister. 409 if already reviewed |

`{role}` is `agents` or `landlords`. `:id` is the submission UUID; the admin routes resolve it against both submission tables. Responses follow the standard envelope (`ResponseEnvelopeInterceptor`).

## Soft-Gate Enforcement

- Listing creation is guarded by a `RequireVerifiedLister` guard (planned, part of the Listings module): listers whose `verification_status !== 'approved'` receive `403 KYC_NOT_APPROVED` with the current status embedded so the frontend can render the correct CTA ("submit your ID" vs. "awaiting review" vs. "submission rejected").
- Browse, search, favourites, inspection requests, and messaging require only a verified email — no KYC.
- **Verified badge on listings:** snapshot semantics — the lister's verification status is denormalized onto the listing row at publish time ("verified at time of listing"), not live-joined.

## Security Protections

1. **Audit trail:** every review records `reviewed_by`, `reviewed_at`, and (on rejection) a mandatory reason. Admin actions on submissions are logged.
2. **Attempt cap:** 3 submissions maximum per account, enforced in the service layer and via the `attempt` column; further submissions respond `403 KYC_ATTEMPTS_EXHAUSTED`.
3. **Single active submission:** enforced by partial unique index; concurrent submits respond `409 KYC_ALREADY_PENDING`.
4. **File constraints:** uploads restricted to image MIME types (`image/jpeg`, `image/png`, `image/webp`) and a maximum size (5 MB); stored outside any executable path with generated file names.
5. **No BVN, ever:** see Document Policy. Requests containing unexpected identity fields are rejected by strict DTO validation (`whitelist: true`, `forbidNonWhitelisted: true`).
6. **Access control:** documents live in a private Cloudinary folder (`authenticated` access mode) and are delivered only through authenticated endpoints that stream bytes via short-lived signed URLs; document references are never included in public listing responses.
7. **Rate limiting:** KYC submission endpoints throttled in line with auth endpoints (10 requests per minute per IP).
